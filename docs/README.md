# Documentation

These pages explain how the starter vault is meant to work: the thinking behind it, how to tag and decorate it, the routines that keep it healthy, and how the pieces fit together. Start with the philosophy if you want the reasoning, or jump to a workflow if you want to start using it today.

| Page | Read it to learn |
| --- | --- |
| [Philosophy](philosophy.md) | Why records with views on top, templates as schema, plain files, an honest record, and preview-before-write |
| [Tagging](tagging.md) | The `type` and tag taxonomy, rules for new tags, how Bases use them, and a cleanup checklist |
| [Aesthetics](aesthetics.md) | Theme, Iconize with Twemoji, pixel-art banners, CSS snippets, Pretty Properties, and consistency rules |
| [Workflows](workflows.md) | The daily loop, the weekly review, the vault garden, and where each skill fits |
| [Architecture](architecture.md) | The five layers, who may write where, links and area maps, and the optional session importer |
| [Obsidian setup](obsidian-setup.md) | Recommended core and community plugins, Sync versus git, and MCP and CLI access |
| [Configuration](CONFIG.md) | The `.vault-skills.yaml` contract every skill and script follows |
| [Scripts](../scripts/README.md) | The checker, link tools, map builders, banner engine, and make targets |

## Suggested reading order

1. [Philosophy](philosophy.md), for the principles every other page assumes.
2. [Obsidian setup](obsidian-setup.md), to get the plugins in place.
3. [Workflows](workflows.md), to start the daily loop.
4. [Tagging](tagging.md) and [Aesthetics](aesthetics.md), when you are ready to tune the vault.
5. [Architecture](architecture.md), when you want to extend it.

## Diagrams

Diagrams are written in Mermaid, which GitHub and Obsidian both render. If a destination cannot render Mermaid, use `/vault-skills:mermaid-image` to turn a diagram into a picture.
