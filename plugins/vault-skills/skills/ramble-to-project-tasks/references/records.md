# Where each kind of item goes

Paths are relative to the vault root; `<people>`, `<projects>`, `<tasks>`, `<meetings>`, `<templates>` are the `folders.*` values from `.vault-skills.yaml`. "Template" means a file in `<templates>`; read it before creating a note, keep its frontmatter keys in order, and resolve its Templater expressions. Kinds marked *(if the vault has it)* have no configured folder: use the folder and template the vault already has for that kind (search for it), and if there is none, do not create one; file the item under the nearest person or project note or the task inbox. Each hub's Tasks query picks up open tasks in its folder, so a task filed in the record shows up there.

| Kind | Existing record to update | New note (template → path) | Notes |
| --- | --- | --- | --- |
| Person fact | `<people>/**/<Name>.md`, a bullet under its notes section | `templates.person` → `<people>/<Name>.md` (or `/vault-skills:add-person`) | Create a person note only when the user gives a fact worth keeping; a passing mention is just a link or plain text. |
| Conversation (call, message, email, in person) *(if the vault has it)* | none | the vault's communication template → its communications folder, named `<YYYY-MM-DD> <Topic> - <Person> <Kind>` | `person` is a quoted link to the person note. Record what was said under a communication section and the user's explicit next steps under follow-up. For a work email, find it with the mail skill when `integrations.calendar_mail` is configured to get the exact date, sender and subject; summarize rather than paste. Mark it pending only when a reply or action is outstanding. |
| Event *(if the vault has it)* | the matching event note | event template → events folder, `<YYYY-MM-DD> <Event>` | Statuses such as planned, tentative, happened, cancelled: reuse the vault's. Do not guess times or timezones. Work calendar events do not need a note unless asked. |
| Place *(if the vault has it)* | the matching place note | place template → places folder | Restaurants, shops, venues. |
| Recipe *(if the vault has it)* | the matching recipe note | recipe template → recipes folder | Keep quantities and steps exactly as said. |
| Trip *(if the vault has it)* | the matching trip note | trip template → trips folder | Tasks go in its actions section; dated notes in its journal section. Keep tentative plans separate from booked ones. |
| Vehicle *(if the vault has it)* | the vehicle note, dated bullet in its maintenance log | vehicle template → vehicles folder | Record odometer readings with their date. |
| Document *(if the vault has it)* | the matching document note | document template → documents folder | IDs, policies, leases. Never write secrets or full account numbers into the note; ask where the original is kept. |
| Ticket update | `<tasks>/<status folder>/<Title>.md` (find it by `url:`), under its work-log section in today's day heading (newest first; create the day heading above the previous one) | Do not create. Ask the user to run `/vault-skills:jira-to-obsidian-sync` | Add a short entry marked as from a ramble with the time. Do not change `status:`; the sync owns it. |
| Project update | The project's main note: a dated bullet in its log or changelog section if it has one, otherwise under the most fitting section. Bump `reviewed` to today if the note has it. | none | Automation or skill items, if the vault tracks them, take dated changelog entries, newest first. |
| New project | none | `templates.project` → `<projects>/<Name>/<Name>.md` | Only after the user confirms. Reuse the vault's status and category values. |
| Work note that is not a ticket or project | The matching rolling log under `<meetings>/` only if the user is describing a meeting (find which meeting, and its date, from the calendar when available); otherwise the task inbox | none | Do not touch standup sections owned by another skill. |
| Health note *(if the vault has it)* | Existing note in the vault's health area | Match the nearest existing health note's layout | Preserve wording, dates and measurements. No advice, and no copy in the daily ramble block. |
| Loose task | none | Today's daily note → its task-inbox heading | Use the vault's work or personal tag. |
| Idea with no home | none | Today's daily note → task inbox as a plain bullet (not a checkbox), or an ideas folder under `<projects>` if the user calls it a project idea | Do not turn musings into tasks. |
